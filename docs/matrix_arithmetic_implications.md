# Implications of "Fully Homomorphic Encryption for Matrix Arithmetic"

Date: 2026-04-30

Source:
`/home/user/experiments/Fully Homomorphic Encryption for Matrix Arithmetic.pdf`

## Short Verdict

The paper does not directly improve the current HElib BGV bootstrapping
implementation.  Its construction changes the plaintext/ciphertext
representation by moving to a multivariate ring

```text
R' = Z_q[i][X,Y,W] / (X^n - i, Y^n - i, Phi_p(W)),
```

with a secret key in the smaller subring

```text
R = Z_q[i][X,W] / (X^n - i, Phi_p(W)).
```

That is a scheme-level redesign, not a drop-in replacement for HElib's current
slot encoding or its digit-extraction polynomial.  However, it gives a useful
new theoretical language for our order-four sparse cleaner and suggests one
ambitious future route for homomorphic linear transforms.

## What Transfers Cleanly

### 1. Gaussian-unit interpretation of our `A=256`

Our current best auxiliary radix satisfies

```text
256^2 = -1 mod 65537.
```

The matrix-arithmetic paper systematically builds its encoding over Gaussian
integers `Z[i]`, and then uses a square root of `-1` modulo `q` to split
`Z_q[i]` into two `Z_q` components.  This gives a better conceptual explanation
of our result:

```text
The order-four radix is not an ad hoc SAT artifact.  It is a finite-field
Gaussian unit, and the sparse cleaner is a character projection under the
C4 action X -> A X.
```

This strengthens the theory section of our paper.  The current polynomial

```text
P_256(X) = 32769 X + X^3 Q(X^4)
```

can be described as a projection onto two character components of the cyclic
group generated by multiplication by `A`.

### 2. Trace/projection language

The paper realizes matrix multiplication as a trace, i.e. a constant-term
projection over an auxiliary variable.  Our exact cleaner can also be viewed as
a projection problem:

```text
h A + lo  ->  lo,       |h|, |lo| <= B.
```

For `A^2=-1`, multiplication by `A` rotates the support geometry, and the
cleaner can be decomposed by cyclic-group idempotents.  This suggests replacing
the phrase "SAT found a sparse polynomial" by the stronger phrase:

```text
structured auxiliary-radix search plus character-projected exact interpolation.
```

SAT remains useful for verification and bounded search, but the reason the
answer is sparse is algebraic.

### 3. Better negative boundary for linear-transform claims

The paper's main speedup comes from avoiding repeated rotations and
slot/coeff conversions by using a new matrix-native encoding.  This supports
our earlier conclusion:

```text
It is unlikely that current HElib coeffToSlot/slotToCoeff can be radically
accelerated by only adding a planner at the Ctxt layer.
```

A real asymptotic linear-transform improvement probably needs a representation
change or a deeper key-switching change.

## What Does Not Transfer Directly

### 1. It does not reduce our digit-extraction degree

For fixed support

```text
S_A = { h A + lo : |h|, |lo| <= 17 },
```

the degree-`< |S_A|` exact cleaner is unique.  The matrix-arithmetic paper does
not change that interpolation fact.  Our stable claim remains sparsity and
evaluator cost, not lower minimal degree.

### 2. It is not plug-compatible with HElib BGV bootstrapping

The paper's ciphertext is over `R'`, but the secret is over `R`.  This is why
some operations along the `Y` direction are coefficient permutations rather
than key-switching operations.  Standard HElib ciphertexts do not have this
extra `Y` dimension, so this advantage cannot be claimed without changing the
scheme.

### 3. The integer-matrix BGV setting has plaintext-modulus constraints

In the paper's integer section, the plaintext modulus `t` must satisfy

```text
t = 1 mod 4 n p
```

where the paper's `p` is the `W`-cyclotomic parameter, not our plaintext prime.
Our current BGV plaintext prime is `65537`, so this condition heavily restricts
available `n,p` choices and prevents a straightforward reuse of their full
integer matrix batching at the current parameter set.

## New Research Directions

### Route A: Character-projected cleaner search

This is the most realistic extension of our current paper.

Experiment:

1. Enumerate auxiliary radices `A` with small algebraic order, e.g.
   `A^2=-1`, `A^4=-1`, `A^8=1`.
2. Reject candidates with support collisions.
3. Interpolate the exact cleaner.
4. Decompose nonzero exponents by residue class modulo the order.
5. Estimate specialized evaluator cost:

```text
P(X) = sum_r X^r Q_r(X^d).
```

For the current target `p=65537,B=17`, the existing scan still favors
`A=256`: it has 307 nonzero terms, while generic `A=35` has 612.  Some
higher-order candidates do not help; for example, order-16 style `A=64` still
has 612 terms, and `A=16`/`A=4096` collide on the support.  The value of this
route is to generalize the method across more BGV parameter sets.

Paper claim if successful:

```text
We give a group-character search framework for exact cleaning polynomials and
show that the order-four Gaussian-unit candidate is optimal among scanned
low-order radices for the target large-prime BGV setting.
```

### Route B: Matrix-aware bootstrapping representation

This is a larger follow-up project, not a safe claim for the current paper.

Idea:

Use the paper's asymmetric design principle, where the secret key lives in a
smaller subring and one message dimension is key-switch-free.  A future
bootstrapping design could place parts of `slotToCoeff`/`coeffToSlot` along the
extra `Y` dimension so that some permutations become coefficient permutations
instead of automorphisms plus key switching.

Required work:

1. Define a BGV-compatible multivariate plaintext ring.
2. Redesign packing so bootstrapping linear maps align with the `Y` dimension.
3. Implement new key-switching keys equivalent to `Switchsmall` and `Switchbig`.
4. Show that bootstrapping can refresh each `Y` coefficient without losing the
   matrix layout.

This is a possible second-paper direction.  It is not a patch to HElib.

### Route C: Trace-style explanation of homomorphic linear maps

The trace viewpoint may still help our writing even without implementation.
HElib's bootstrapping linear transforms are large structured linear maps.  We
can describe the failed LC-AKS/BSGS attempts as staying within the old vector
slot representation, while the matrix-arithmetic paper shows why a deeper
encoding change can remove rotations more fundamentally.

This is useful in the related-work and future-work sections:

```text
Our contribution optimizes the nonlinear cleaning polynomial inside the
existing HElib pipeline; matrix-native encodings suggest an orthogonal way to
attack the linear-transform bottleneck by changing the underlying message
layout.
```

## Recommendation

For the current article, do not change the main experimental claim.  Keep the
main result as:

```text
finite-field Gaussian-unit auxiliary radix
-> sparse exact cleaner
-> order-four specialized evaluator
-> measured HElib BGV bootstrapping speedup.
```

Add the matrix-arithmetic paper as motivation for two refinements:

1. theoretical framing via Gaussian units and character projections;
2. future work on matrix-aware bootstrapping linear transforms.

The highest-value next experiment is Route A: broaden the structured aux search
from one order-four case to a small family of character-projected cleaner
decompositions across multiple BGV parameter sets.

## General `A,p,B` Parameter Theorem

There are two different parameter questions.

### Exact cleaner correctness

For any bound `B >= 1` and any prime

```text
p > 4 B (B + 1),
```

the generic radix

```text
A = 2 B + 1
```

is collision-free on the square support

```text
S_A = { h A + lo : |h|, |lo| <= B }.
```

Indeed, if `(h,lo)` and `(h',lo')` collide, then

```text
u A + v = 0 mod p,
|u|, |v| <= 2B,
```

where `u=h-h'` and `v=lo-lo'`.  If `u=0`, then `v=0` because
`|v|<p`.  If `u != 0`, then with `A=2B+1`,

```text
1 <= |uA+v| <= 2B A + 2B = 4B(B+1) < p,
```

so `uA+v` cannot be a nonzero multiple of `p`.  Hence the support has
`(2B+1)^2` distinct points and the exact cleaner exists uniquely as the
degree-`<|S_A|` interpolation polynomial over `F_p`.

This is the sense in which `p` can be "arbitrary": any sufficiently large
prime works for correctness after choosing a collision-free radix.

### Order-four sparse cleaner

The stronger sparse structure used by this artifact is not available for every
prime.  For prime `p`, an element `A` with

```text
A^2 = -1 mod p
```

exists if and only if

```text
p = 1 mod 4.
```

Moreover, if

```text
p > 8 B^2,
```

then any such square root of `-1` is automatically collision-free on the
bounded support.  A collision would imply

```text
uA + v = 0 mod p,
|u|, |v| <= 2B,
```

and therefore, after squaring and using `A^2=-1`,

```text
u^2 + v^2 = 0 mod p.
```

But for a nonzero difference vector,

```text
0 < u^2 + v^2 <= 8B^2 < p,
```

which is impossible.  On this collision-free support, multiplication by `A`
maps `(h,lo)` to `(lo,-h)`, giving the identity

```text
P_A(A X) + A P_A(X) = A X
```

for the canonical exact cleaner.  Coefficient comparison then forces

```text
P_A(X) = (1/2) X + X^3 Q(X^4).
```

Thus, for the paper's main optimization, `p` is not completely arbitrary:
the clean general condition is

```text
p prime, p = 1 mod 4, p > 8B^2, choose A^2 = -1 mod p.
```

For the target `B=17`, this lower bound is `p>2312`; `p=65537` satisfies it,
and `A=256` is a square root of `-1`.  The other root, `p-A=65281`, has the
same field action but is not the preferred HElib integer representative because
the implementation also uses the integer radix in scaling-related code paths.
